# แผนพัฒนา TradeLog ระยะถัดไป

## เป้าหมาย
ทำให้แอปน่าใช้ในชีวิตประจำวันมากขึ้น: บันทึกไม้ได้เร็ว ข้อมูลไม่ผิดพลาด ค้นหาและทบทวนได้ง่าย และวิเคราะห์แล้วนำไปปรับพฤติกรรมการเทรดได้จริง โดยยังรักษาแนวคิดเดิมคือ post-trade journal, R-Multiple และ checklist เป็นแกนหลัก

## สิ่งที่มีอยู่แล้ว
- Dashboard มี Total R, Win Rate, Profit Factor, Avg R:R, กราฟสะสม R, เวลา/วัน, streak และ popup Insights
- Trade Form รองรับ Win/Loss/Break-even/Missed/Canceled, duration, conditions, tags, รูปภาพ และ Custom Metrics
- Trade History รองรับค้นหา กรอง เรียงลำดับ เลือกหลายรายการ ลบ/ติด tag และ CSV Import/Export
- Recap Quiz รองรับเลือกช่วงเวลา ตอบ direction/เข้า-ไม่เข้า/condition และเก็บสถิติแยก condition
- มีหลาย profile, Quick Notes, Calendar และระบบจัดการ Conditions/Tags/Metrics

## ลำดับที่แนะนำ

### ระยะ 1 — ความถูกต้องและความน่าเชื่อถือของข้อมูล
1. ตรวจและแก้การแยกข้อมูลตาม Profile ให้ครบทุกจุด โดยเฉพาะ queries ของ conditions, tags, trade relations และ quiz ให้ไม่ปะปนระหว่าง profile
2. เพิ่ม validation ที่ Custom Metrics ให้ตรวจ min/max, จำนวนทศนิยม, ค่าว่าง และค่าที่ไม่ใช่ตัวเลขทั้งตอนกรอกและ Import CSV
3. ทำให้การบันทึก/แก้ไขไม้เป็น atomic มากขึ้น: หากบันทึก relation หรือ metric ไม่สำเร็จ ต้องแจ้งชัดเจนและไม่ทิ้งข้อมูลครึ่งชุด
4. ปรับ CSV Import ให้รายงานแถวที่ผิดแบบแก้ไขได้ง่าย และป้องกันการนำเข้า date/ผลลัพธ์/R ที่ตีความผิดโดยไม่ตั้งใจ
5. เพิ่ม loading, empty, error และ retry states ในหน้าหลักที่อ่านข้อมูลจาก backend

**ผลลัพธ์:** ผู้ใช้มั่นใจได้ว่าตัวเลข Dashboard และข้อมูลแต่ละ Profile ถูกต้อง ก่อนเพิ่มฟีเจอร์วิเคราะห์ต่อ

### ระยะ 2 — ทำให้การบันทึกประจำวันเร็วขึ้น
1. เพิ่ม preset/ค่าล่าสุดสำหรับ Asset, Direction, Conditions, Tags และ Custom Metrics ที่ใช้บ่อย โดยให้แก้ไขได้ก่อนบันทึก
2. เพิ่ม duplicate trade / ใช้ข้อมูลจากไม้ก่อนหน้าเป็นแบบร่าง เพื่อลดการกรอกซ้ำ แต่ต้องไม่สร้างข้อมูลจนกว่าจะกดบันทึก
3. ปรับ Trade Form ให้แบ่งเป็นส่วนที่สั้นและสแกนง่ายบนมือถือ พร้อมแสดงฟิลด์ Metrics เฉพาะรายการที่เปิดใช้งาน
4. เพิ่ม draft อัตโนมัติในฟอร์ม เพื่อป้องกันข้อมูลหายเมื่อสลับหน้า/ปิดหน้าต่างโดยไม่ตั้งใจ
5. เพิ่มตัวกรอง Metrics ใน Trade History เช่น Fibo มากกว่า/น้อยกว่า, Points อยู่ในช่วง และมี/ไม่มีค่า

**ผลลัพธ์:** การบันทึกหนึ่งไม้เร็วขึ้นและ Custom Metrics กลายเป็นข้อมูลที่กรอกได้จริง ไม่ใช่ฟีเจอร์ที่ผู้ใช้ข้าม

### ระยะ 3 — เปลี่ยนข้อมูลเป็นข้อสรุปที่ใช้ตัดสินใจได้
1. ขยาย Metrics Analysis ให้แสดงจำนวนตัวอย่างของแต่ละช่วงค่าอย่างชัดเจน และซ่อน/เตือนผลลัพธ์ที่มีข้อมูลน้อยเกินไป
2. เพิ่มการเปรียบเทียบ Metric กับ Result, Direction, Condition, Asset และช่วงเวลา เช่น Fibo ช่วงใดมี Avg R สูงกว่า โดยไม่สรุปเกินข้อมูล
3. เพิ่ม drawdown, expectancy, average win/loss, best/worst trade และสถิติ rolling ล่าสุดบน Dashboard
4. เพิ่มการ drill-down จากการ์ด/Insight ไปหน้า Trades พร้อม filter ที่เกี่ยวข้อง เช่น คลิกช่วง Fibo แล้วเห็นไม้ชุดนั้นทันที
5. ปรับ Rule-based Insights ให้แสดง sample size และระดับความมั่นใจเบื้องต้น เพื่อไม่ให้ผู้ใช้ตัดสินจากข้อมูลเพียง 1–2 ไม้

**ผลลัพธ์:** Dashboard ช่วยตอบคำถามว่า “อะไรทำให้ผลลัพธ์ดีหรือแย่” และพาไปตรวจไม้ต้นทางได้ทันที

### ระยะ 4 — ระบบทบทวนและวินัยที่ใช้งานต่อเนื่อง
1. เพิ่ม Quiz summary ที่แยก direction accuracy, entry decision และ condition recall ให้เห็นแนวโน้มรายสัปดาห์/เดือน
2. เพิ่มการทบทวนไม้ที่พลาดบ่อยหรือมีผลลัพธ์ผิดปกติ โดยสุ่มจากชุดที่ผู้ใช้เลือกได้
3. เพิ่ม weekly/monthly review: Total R, expectancy, drawdown, เงื่อนไขเด่น, พฤติกรรมเสี่ยง และบทเรียนจาก recap
4. เพิ่ม export รายงานสรุปช่วงเวลาเป็น CSV ก่อน และค่อยพิจารณา PDF/รูปภาพเมื่อรูปแบบข้อมูลนิ่งแล้ว

**ผลลัพธ์:** แอปไม่ใช่แค่ที่เก็บข้อมูล แต่เป็นวงจร “บันทึก → วิเคราะห์ → ทบทวน → ปรับปรุง”

## งานที่ควรเริ่มก่อน
เริ่มจาก **ระยะ 1** โดยตรวจ Profile isolation และ validation ของ Custom Metrics/CSV ก่อน จากนั้นทำ **ระยะ 2 ข้อ 1–3** เพื่อให้การกรอกข้อมูลในแต่ละวันลื่นขึ้น แล้วจึงขยาย analytics ในระยะ 3 เมื่อข้อมูลมีคุณภาพเพียงพอ

## ขอบเขตที่ยังไม่แนะนำตอนนี้
- ยังไม่เพิ่ม AI สร้างคำแนะนำ เพราะ rule-based insights ที่มีอยู่เหมาะกับข้อมูลส่วนตัวมากกว่า และควรแก้ความถูกต้องของข้อมูลก่อน
- ยังไม่เพิ่มการเก็บราคา/ระบบ pre-trade เนื่องจากขัดกับแนวคิด post-trade และ R-Multiple ของแอป
- ยังไม่ทำ PDF ซับซ้อนก่อนที่รูปแบบรายงานและตัวชี้วัดจะนิ่ง

## รายละเอียดทางเทคนิค
- ตรวจ query และ relation ทุกหน้าที่ใช้ `profile_id` ให้ filter ด้วย active profile อย่างสม่ำเสมอ
- รวมกติกาการ parse/validate metric และ CSV ไว้ใน utility เดียว เพื่อให้ Trade Form และ Import ใช้กติกาเดียวกัน
- ใช้ query invalidation หรือ mutation flow ที่ทำให้ UI สะท้อนผลลัพธ์จริงหลังบันทึก/ลบ/แก้ไข
- รักษา integration ของ Electron และ fallback ของ web preview ทุกครั้งที่แก้ Trade Form, Quick Notes หรือ navigation
- ทดสอบ responsive ที่ความกว้าง 384px และ flow หลัก: สร้างไม้, แก้ไข, import, เปลี่ยน profile, dashboard และ quiz
